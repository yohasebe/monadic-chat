# プライバシーフィルター（個人情報マスキング）

## 概要

プライバシーフィルターは、ユーザーメッセージに含まれる個人を特定可能な情報（PII）を AI プロバイダに送信する前にマスクし、AI の応答に対してマスクされた情報を元の値に復元します。検出処理は別の Docker コンテナ（Microsoft Presidio + spaCy）でローカルに実行され、PII が LLM への往復経路で外部に出ることはありません。

プライバシーコンテナは Monadic Chat の標準コンテナセットに含まれているため、初回起動時から利用可能です。マスキングは、アプリごとのトグルで会話ごとにオンにします。

## 利用が向く場面

- 実在する氏名・メールアドレス・電話番号を含むメールや文書を作成するとき。
- 個人情報を含むテキストを翻訳するとき。
- 機密性のある識別子を含むスニペットを、手作業で書き換えずに共有したいとき。

## インストール

プライバシーコンテナは、配布されているイメージがダウンロードされ、Monadic Chat とともに起動します。対応するすべての言語モデルがイメージに含まれており、英語は常に有効です。

英語以外のコンテンツに対するマスキングを有効にするには、追加言語をオンにします:

1. **Actions → Install Options** を開きます。
2. **Privacy Filter — Additional Languages** セクションを探します。
3. ドイツ語 (de)、スペイン語 (es)、フランス語 (fr)、イタリア語 (it)、日本語 (ja)、オランダ語 (nl)、ポルトガル語 (pt)、中国語 (zh) から必要な言語にチェックを入れます。英語は常に有効で外せません。
4. **Save** をクリックします。リビルドは不要です — プライバシーコンテナが起動中であれば新しい言語セットで自動的に再起動されます。Monadic Chat のサーバーが稼働中の場合は、セッションごとのトグルが新しい言語を認識できるよう、サーバーを再起動（Stop/Start）してください。

言語選択は実行時設定です。言語の有効化・無効化はサーバーが読み込むモデルを切り替えるだけで、コンテナイメージは変わりません。

実行時のオプトアウト: `~/monadic/config/env` に `PRIVACY_FILTER=false` を設定すると、プライバシーコンテナは起動されなくなります。`true` に戻すまでトグルは無効化され、ツールチップには「Privacy Filter is disabled.」が表示されます。

## セッションごとのトグル

プライバシーフィルターをサポートするアプリでは、Session Controls パネルに **Privacy Filter** トグルが表示されます。

- **Start Session** を押す前にオンにすると、そのセッションのマスキングが有効になります。
- セッションが始まると、トグルはロックされます。**Reset** を押すか別のアプリに切り替えると、新しい会話のために編集可能な状態に戻ります。セッションを始めた後にフィルターを使うには、**Reset** を押してください。
- トグルをオンにした会話は Private です。フィルターを起動できなかったときも、後でオフに戻したときも、[会話の履歴](../basic-usage/web-interface.md#chat-history-panel)には残しません。Private の会話のメッセージも、モデルには送ります。伏せるのは、フィルターがオンのあいだだけです。
- 最後の選択はアプリごとに記憶され、トグルはその状態で始まります（最初にオンにするまではオフです）。

トグルが無効化されているときは、ホバーすると理由が表示されます:

- *This app does not support Privacy Filter.* — アプリの MDSL に `privacy` ブロックが宣言されていません。
- *Privacy Filter is disabled.* — 環境変数 `PRIVACY_FILTER=false` が設定されており、プライバシーコンテナが起動していません。
- *Privacy Filter is not installed for this language. Install via Settings → Install Options.* — サイドバーで指定されている `conversation_language` が、有効化されている言語に含まれていません。Actions → Install Options で対象言語を有効化するか（保存時に反映されます）、conversation_language を有効な言語に切り替えてください。

## 言語の選択

セッショントグルの有効・無効、およびマスキング言語はサイドバーの **conversation_language** に従って決まります:

| サイドバーの conversation_language | マスキング言語 | トグル |
|---|---|---|
| Automatic | メッセージから判別（判別するまでは英語） | 有効 |
| English (en) | 英語 | 有効 |
| インストール済みの非英語言語（ja、de、fr など） | その言語（対応する spaCy NER モデル） | 有効 |
| 未インストールの言語（韓国語など） | — | 無効、ツールチップ表示 |

**Automatic** では、メッセージが有効な言語のどれかとして確かに判別されるまでは英語としてマスクし、判別した後はそのセッションをその言語で扱います。英語以外の内容をマスクするときは、最初のメッセージからその言語で扱われるように、サイドバーで conversation_language を明示的に指定してください。

日本語には専用の追加処理があります: `lang_used` が `ja` の場合、プライバシーコンテナは PERSON のスパン末尾の敬称（`さん`、`様`、`先生`、`君` など）をトリミングし、placeholder には実際の氏名のみが入るようにします。

## インジケーターとレジストリ

フィルターがアクティブな場合、チャットヘッダーにインジケーターが表示されます:

- **Privacy ready**（灰色のアンロックアイコン）: フィルターはオンですが、まだエンティティはマスクされていません。
- **Privacy ON (N)**（緑のロックアイコンとカウント）: 復元用のプレースホルダーが現在 N 件登録されています。
- **Privacy error**（赤）: プライバシーコンテナへ到達できませんでした。Docker が起動していてコンテナが正常か確認してください。

プライバシーコンテナが動いていなければ、フィルターを使うアプリを選んだときに起動します。言語モデルの読み込みには時間がかかります（初回は 1 分ほど）。準備ができる前にフィルターをオンにすると、チェックはオフのままで、起動中であることが表示されます。少し待ってから、もう一度オンにしてください。コンテナが起動しなかったときは、そのことが表示されます。

conversation_language が **Automatic** のときは、セッションの言語が決まると、インジケーターの横に小さな言語バッジ（言語のアイコンと、たとえば **ja**）が表示されます。サイドバーで選んだ言語では表示されません。

インジケーターをクリックすると **Privacy Registry** が開き、各プレースホルダーと元の値、エンティティの種類（PERSON、EMAIL_ADDRESS など）が一覧表示されます。会話をエクスポートするボタンもあります。レジストリはセッションメモリ内にのみ保持され、ディスク上の会話ログには書き込まれません。

## アンマスクハイライト

会話カード（ユーザー入力・アシスタント応答の双方）では、Privacy Filter が現在追跡しているすべての値に下線が引かれます。同じプレースホルダーは常に同じ色を使うため、たとえば同じ氏名はすべてのカードで同じ青い下線になり、別の氏名は別の色で表示されます。背景は常にグレーで、色相は下線にだけ反映されるためレイアウトが派手になりません。

下線にマウスを乗せると、その値が経由したプレースホルダー（例: *Tracked as <<PERSON_1>>*) が tooltip として表示されます。下線はマークダウンレンダリングの後に引かれます。`<code>` と `<pre>` のブロックには引かれず、リンクではリンクの文字にだけ引かれて、リンクそのものは変わりません。

ハイライトは表示用のみで、LLM への送信内容には影響しません。下線が引かれていてもいなくても、LLM 通信時には同じレジストリ経由のマスキングを通過します。

## マスクされる対象

デフォルトでは次のエンティティタイプをマスクします:

`PERSON`、`ORGANIZATION`、`EMAIL_ADDRESS`、`URL`、`POSTAL_CODE`、`PHONE_NUMBER`、`CREDIT_CARD`、`IP_ADDRESS`、`IBAN_CODE`、`US_SSN`、`US_MEDICAL_LICENSE`。

`LOCATION`（「Tokyo」など）はデフォルトに含まれず、`DATE_TIME`（「Friday」など）はマスクされないので、日常的な表現はそのまま残ります。

アプリ作者は MDSL でマスク対象を調整できます:

```ruby
privacy do
  enabled true
  mask_types [:person, :email, :address]  # :address adds LOCATION
end
```

指定できる値は `:person`、`:organization`、`:email`、`:url`、`:address`、`:postal_code`、`:phone`、`:credit_card`、`:ip`、`:iban`、`:us_ssn`、`:medical_license` です。`privacy` ブロックでは、`score_threshold`（マスクするのに必要な検出の確からしさ。0〜1、既定 0.4）、`honorific_trim`（名前から日本語の敬称を除く。既定はオン）、`on_failure`（マスクに失敗したときの動作。既定の `:block` はメッセージを送らず、`:pass` はマスクせずに送ります。ただし会話に印を付けた語があるときは送りません）も指定できます。

## 伏せる語に印を付ける :id=marking-words

検出で見つからない名前などは、自分で印を付けられます。入力欄で語を選び、入力欄の下の **Mask** ボタンを押します（Ctrl/Cmd+Shift+K でも同じ）。ボタンの横のメニューでは、人名の代わりに組織・場所・メールアドレス・電話番号・URL・日付として印を付けられます。語は `⟦江戸川今太郎⟧`、種類を付けると `⟦Acme社|organization⟧` のように囲まれます。括弧を自分で入力してもかまいません。

送信すると印は取り除かれ（会話には書いたとおりの文が表示されます）、語はその会話で保持されます。

- 送信の前に伏せ字にし、その後もその会話では、印を付け直さなくても伏せ字にします。
- 会話のためにモデルへ送るメッセージとツールの結果、会話のために送られるもの（セカンドオピニオン、Verify、AI User、Session Context の抽出）で伏せ字にします。読み上げでも置き換え、印を付けた語がある間は Live Conversation（音声での会話）は使えません。
- 印を付けた語が、伏せ字にしない部分（システムプロンプト、ツールの定義、アプリの設定）にもある場合は、何も送らずにエラーで知らせます。確認は他の語の一部としての出現も見るため、短い語やよく使われる語（アプリの設定やツールが使う "auto"、"query"、"user" など）に印を付けると会話が止まります。印を消すには Reset を押してください。
- 添付した画像・PDF・音声はそのまま送られます。その中身は、印を付けた語について確認しません。
- 印を付けた語がある間は、プライバシーフィルターがオフの状態では、その会話について何も送りません。オンに戻すか、Reset で会話を終えてください（Reset で印を付けた語は消えます）。
- インポートした会話ファイルの、自分のメッセージに付いている印も同じように読み取ります（Monadic Chat が書き出したファイルは印を取り除いた後のものなので、中の括弧は書いたとおりに残ります）。
- 会話に印を付けた語がある間は、Monadic Chat のサーバーがその会話のために外部のサービスへ送るリクエストを、送る瞬間にすべて確認し、語が含まれていれば送りません。確認するのは、リクエストのアドレス、本文のテキスト（JSON、フォーム、アップロードのテキスト欄とファイル名）、音声の接続で送るテキストのメッセージです。会話のために送るもの、つまりツール（ウェブ検索、画像生成、読み上げ）や、会話から使う MCP サーバーもこの対象です。確認に使うのはその会話の語だけで、どの会話にも属さないリクエスト（別のアプリケーションから使う MCP サーバーなど）は、印の語の確認の対象外です。対象外は、アップロードするファイルと音声の中身、アプリが別に動かすプログラム（コンテナ内のスクリプト、実行したコード）、このコンピューター上のサービス（ローカルのモデルなど）です。
- 読めない印（閉じていない、入れ子、行をまたぐ、知らない種類）は受け付けず、メッセージは送りません。括弧そのものを書くときは、前にバックスラッシュを付けます（`\⟦`、`\⟧`）。

印を付けた語を使うには、最新のプライバシーコンテナが必要です。古いコンテナのままでは、印を付けた語がある会話は、コンテナを更新するまで送られません。

**Restored** のエクスポートは印を付けた語を保持するため、インポートした会話でも伏せ字が続きます。**Masked** のエクスポートでは語も伏せ字になり、語そのものは含まれません。そのファイルをインポートした後は、もう一度印を付けてください。

## Text-to-Speech (TTS) のサニタイズ

Privacy Filter が有効なときは、TTS 再生（カードごとの **Play** ボタン、Auto-Speech 経路、システムの **TTS** テスト）も追跡中の PII をストリーミングバッファと同じ短いラベル（例: 「PERSON 1」「EMAIL ADDRESS 1」）に置換してから音声合成 API に渡します。これにより、クラウド TTS API（OpenAI / Gemini / ElevenLabs など）に原文の氏名・住所・電話番号が渡ることはなくなり、長いメールアドレスを 1 文字ずつ読み上げるような UX も避けられます。

Web Speech API（ブラウザ内蔵合成）も同じサニタイザーを通ります。音声生成自体はローカルで行われますが、合成器に渡すテキストはクラウド版と同一のためカード越しに UX が一貫します。

## Knowledge Base への保存と検索

Privacy Filter を使うアプリは Knowledge Base に保存しません。対応表は [アプリ別 Privacy / KB 対応表](../basic-usage/basic-apps.md#privacy-kb-by-app) を参照してください。それらのアプリと、Knowledge Base を使わないアプリでは、Knowledge Base のパネルは表示されたまま操作が無効になり、ツールチップで理由が表示されます。

Privacy 用のアプリで扱った会話を残したい場合は **Privacy Export**（暗号化 + 必要に応じた masked モード）を使ってください — 後述の節を参照。

Browse の表では、項目のタイトルや source にメールアドレスや電話番号らしきものが含まれているとき、タイトルの前に控えめな ⚠️ アイコンが表示されます。

### `library_search` 検索

Privacy Filter が有効なセッションで `library_search` が呼ばれた場合、取得したスニペットも同じ Privacy Pipeline を通過してから LLM に送信されます。Knowledge Base に含まれる PII はリクエスト時に placeholder にマスクされ、LLM の応答側では既存の streaming-handler 経路で復元されます。

伏せ字にできない場合（プライバシーサービスが止まっているとき）や、印を付けた語が残る場合は、伏せずに送るのではなく、検索結果を差し控えます。

### Global と App-only スコープ

会話を **Global** スコープで保存すると（デフォルトの **App-only** ではなく）、この Monadic Chat インストール内のすべてのアプリから `library_search` 経由で取得可能になります。保存ダイアログでは、Global を選ぶと、まだ使っていないアプリからも取得できることを知らせる警告が表示されます。明示的に共有したい会話以外は App-only を選んでください。

## 暗号化エクスポート

**Export** ボタンでエクスポートのダイアログが開きます。

- **Encryption**（いつでも選べます）：AES-256-GCM（Argon2id 鍵導出）でファイルを暗号化します。パスフレーズはユーザーが指定します。
- **Content**（セッションでプライバシーフィルターが何かをマスクしたとき）：元の値を復元した内容で、またはプレースホルダーを残した状態で出力します。

セッション内で Privacy がアクティブな場合、ダイアログのデフォルトは **Masked** になっています。意図せずに平文 PII をディスクに書き込まないための安全側デフォルトです。**Restored** を明示的に選んだ上に暗号化を OFF にした組み合わせは、赤い強警告バナーでファイルに何が書き出されるかを説明します。平文 PII を含むファイルにはファイル名末尾に `-PRIVATE` サフィックスが付くため、ダウンロードフォルダの中で識別しやすくなっています。

代表的な組み合わせ:

1. **Encrypted + Restored** — 自分以外には開けない個人アーカイブ。
2. **Encrypted + Masked** — 復号後も PII を露出させない解析ログの共有用。
3. **Plain + Masked** — 実名を含まない簡易な共有サンプル。
4. **Plain + Restored** — `-PRIVATE` 付きの最も警告の強いモード。信頼できるローカル限定のワークフロー用。

パスフレーズの要件: 8 文字以上で確認フィールドが一致すること。強度メーターは情報提供のみで、送信を妨げません。

暗号化エクスポートを再度開くには **Import** ボタンを使い、プロンプトに従ってパスフレーズを入力します。レジストリも会話と一緒に復元されるため、続くメッセージで一貫したマスキングが行えます。

## ドキュメント DB のエクスポート / インポート（Actions メニュー） :id=document-db-export-import

**Actions → Export Document DB** と **Actions → Import Document DB** メニューは qdrant ボリューム全体（保存されたすべての会話・PDF・Knowledge Base エントリ）を対象とします。両メニューとも、実行前に確認ダイアログを表示します。

エクスポートでは次の 2 つから選べます:

- **Encrypt and Export**（デフォルト）: パスフレーズを尋ね、tarball を AES-256-GCM（PBKDF2-SHA256, 600 000 回反復）でエクスポートごとのランダムソルトを使って暗号化し、`monadic-qdrant.tar.gz.enc` を共有フォルダに書き出します。暗号化に成功すると平文の tarball は削除されます。
- **Export Plain**: 暗号化せずに tarball を直接書き出します。ダイアログでは、保存済み会話 / PDF が Privacy Filter の利用状態によらず平文で含まれることを警告します。

インポートはファイル拡張子を自動判別します: `.tar.gz` はそのまま展開され、`.tar.gz.enc` ではパスフレーズを尋ねて一時平文ファイルに復号した後 qdrant ボリュームのインポートを実行し、最後に一時ファイルを削除します。パスフレーズが間違っていたり改ざんされている場合は復号に失敗し（tarball は中途半端に展開されません）、qdrant ボリュームには手が触れられません。

暗号化フォーマット: `[magic 'MQDB'] [version 0x01] [salt 16] [iv 12] [ciphertext] [authTag 16]`。ストリーミング処理可能な構造のため、複数 GB のボリュームでもメモリに乗せきる必要はありません。

## 対応アプリ

次のアプリの MDSL 定義でプライバシーフィルターが有効化されています:

- Mail Composer
- Chat Plus
- Translate
- Second Opinion

その他のアプリは `privacy do` を宣言していないため、トグルは無効のままです。

## 制限事項

- 検出はすべての名前を見つけるわけではありません。日本語では、言語モデルが見つけるものに加えて、敬称（さん、様、氏、先生、くん、君、ちゃん、殿）の前にある 2〜12 文字の漢字・カタカナの名前を全体として伏せ字にします。ひらがなの名前、敬称のない名前、珍しい名前は見つからないことがあります。そのような語には自分で印を付けてください（[伏せる語に印を付ける](#marking-words)）。
- カスタム認識器はプライバシーコンテナのソース（`docker/services/privacy/recognizers/`）に存在します。新しい認識器を追加するにはコンテナの再ビルド（**Actions → Build Privacy Container**）が必要です。
- マスキングはメッセージごとにわずかなレイテンシを追加します（テキスト長によりますが通常 50-200 ms 程度）。各ターンで context 全体（user メッセージと過去の assistant メッセージの両方）を再マスクし、registry の整合性を保ちます。
- マスキングに対応するのは、spaCy のモデルがプライバシーのイメージに含まれている 9 つの言語（英語、ドイツ語、スペイン語、フランス語、イタリア語、日本語、オランダ語、ポルトガル語、中国語）です。これ以外の言語（韓国語、アラビア語など）はプライバシーフィルターの対象外で、サイドバーの conversation_language がそれらに設定されているとセッショントグルは無効化されます。

## 設定リファレンス

`~/monadic/config/env` に保存される設定:

| 変数 | 値 | デフォルト | 説明 |
|---|---|---|---|
| `PRIVACY_FILTER` | `true` / `false` | `true` | 実行時ゲート。`false` に設定するとプライバシーコンテナは起動しません。`true` に戻すまでトグルは無効化されます。 |
| `PRIVACY_LANGS` | カンマ区切りの言語コード | `en` | プライバシーサーバーが起動時に読み込む言語（すべてのモデルはイメージに含まれています）。Actions → Install Options → "Privacy Filter — Additional Languages" で保存すると、英語が自動で加わります。env ファイルを直接編集するときは、`en` を含めてください。対応コード: `en`、`de`、`es`、`fr`、`it`、`ja`、`nl`、`pt`、`zh`。 |
| `PRIVACY_DEV_PORT` | ポート番号 | `8001` | 開発モード時のみ、プライバシーコンテナの HTTP ポートをホストに公開する用途で使われます。 |

Actions → Install Options から `PRIVACY_LANGS` を変更した場合は保存時に反映されます（起動中のプライバシーコンテナは自動的に再起動されます）。env ファイルを直接編集した場合は、Monadic Chat を再起動して新しい値を反映させてください。`PRIVACY_FILTER` を変更した場合は、Monadic Chat の再起動のみで反映されます（再ビルドは不要）。
